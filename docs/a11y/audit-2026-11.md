# WCAG 2.2 AA audit, November 2026

Scope: IO-209. Every signed-in, auth and legal page of the web app, on the mock app (MSW), after the M9 UI changes and IO-197 (project form limits) were merged. Date: 27 Nov 2026.

## How it was done

| Part | Method | Where |
| --- | --- | --- |
| Automated | axe-core 4 through `@axe-core/playwright`, tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa`, `wcag22aa`, every route at 375 and 1280 px, plus popovers open | `e2e/tests/a11y/pages.spec.ts`, runs in CI job `e2e-mock` |
| Keyboard | Playwright presses Tab through each page (up to 70 stops) and reads `document.activeElement`: ring, `elementFromPoint` at its centre, dialog and picker behaviour with Enter and Esc | one-off script, results below |
| Measured | Bounding boxes of every interactive element (2.5.8), `scrollWidth` at 320 px (1.4.10), injected text-spacing CSS (1.4.12), `document.getAnimations()` with and without `prefers-reduced-motion` | one-off script |
| Code reading | Source of the components named in each row | `web/src` |

What was not done: **screen reader pass with VoiceOver (macOS / iOS): not done, needs a human on macOS or iOS.** Pages to cover: assessment and results. No NVDA or TalkBack pass either. 200 % zoom (1.4.4) was checked only by the 320 px reflow (a 1280 px viewport at 400 % is 320 px); no separate 200 % run.

Limits of the method: focus obscuring is tested at the centre point of the focused element, so it can over-report a control that is only partly covered. Colour contrast beyond axe's `color-contrast` rule belongs to IO-210. The run is in `next dev` on the mock app: the Next.js dev overlay (`nextjs-portal`) was ignored in the keyboard results.

## Result of the automated gate

All routes pass at both widths with zero violations, except two real rule violations that are let through by rule and element until fixed (see `KNOWN_ISSUES` in `e2e/helpers/a11y.ts`; delete the entry in the fix PR):

| Rule | WCAG | Issue |
| --- | --- | --- |
| `label-content-name-mismatch` | 2.5.3 Label in Name (A) | IO-219 |
| `link-in-text-block` | 1.4.1 Use of Color (A) | IO-220 |

The old compare route (`/projects/:id/compare`) redirects to the RM view of the versions tab, so it is scanned as the page a person lands on. A test also checks that each known-issue entry still shows on its probe page, so a fixed issue fails the run until its entry is deleted.

Popovers are scanned one by one (Select, MultiSelect, DatePicker, y3 picker, question popup, submit dialog, collapsed cards, dashboard panels). The account menu is not scanned open: Radix hides the page behind a modal menu and axe reports `aria-hidden-focus` on it, a known false positive because focus is trapped in the menu.

Notes:

* Text spacing (1.4.12): with line height 1.5, letter spacing 0.12 em, word spacing 0.16 em and paragraph spacing 2 em, the only clipped text is visually hidden (`srOnly`, `caption`) text. No visible text is cut off.
* Reflow (1.4.10): at 320 px every page has a document width of 320 px except the dashboard (337 px, IO-224). Wide data tables (results table, versions table, admin audit) scroll inside their own area, which the criterion allows for data tables.
* Motion: no animation runs forever on any page; under `prefers-reduced-motion: reduce` no animation or transition is running (`--motion-fast` and `--motion-chart` are 0 ms in `tokens.css`, the donut chart and dashboard motion read the media query). Nothing moves on its own for more than 5 s.
* Target size (2.5.8): the controls under 24 px are listed in IO-223 (assessment group toggles, two link buttons on the project overview, the "forgot password" link, the back links). The login checkbox is 20 px; its label is part of the hit area, so it is not counted.
* Radio cards of the risk plan have a visually hidden input; their label shows the focus ring and is the target, so the hidden input is not counted for 2.4.7 or 2.4.11.

## Criterion by criterion

| Criterion | Result | Evidence |
| --- | --- | --- |
| 2.1.1 Keyboard | Pass | Every flow was reached with Tab, Shift+Tab, Enter, Space, arrows and Esc: login, register, project form (date picker opens with Enter, arrows move the day, Enter picks, Esc closes and gives focus back to the trigger "เปิดปฏิทิน"), assessment (inputs, y3 picker, submit dialog opens with Enter and Esc closes it, focus returns to the submit button), results tabs, plan radio cards (`e2e/mock/plan.spec.ts`), account, admin tables. | 2.1.2 No keyboard trap | Pass | Tab walks through every page (4 to 70 stops) and leaves it; the date picker, y3 picker and dialogs close with Esc. | 2.4.3 Focus order | Pass | Tab order follows the visual order on every page (shell, skip link, header, main). The skip link goes to `#main` |
| 2.4.7 Focus visible | Pass | Every focus stop has an outline or box-shadow ring (`--focus-ring`) |
| 2.4.11 Focus not obscured (minimum) | **Fail** | Assessment: the sticky submit footer covers the centre of focused inputs and buttons. Versions tab: the sticky app header covers focused buttons. Toasts are in a corner region and never covered a focus stop. Issue IO-225 |
